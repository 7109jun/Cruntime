# 문제 해결

## `MSVC headers not found` (종료 코드 4)

표준 라이브러리 헤더를 찾지 못했다는 뜻이다. Visual Studio Build Tools(C++ 작업 로드)와 Windows SDK가 필요하다.

- GUI는 설치 여부를 묻는 창을 띄운다. 동의하면 관리자 권한으로 `winget`이 Build Tools를 설치한다(약 3~6GB). 끝난 뒤 다시 실행한다.
- 메뉴 **설정 → Build Tools 설치...**로도 같은 창을 열 수 있다.
- 직접 설치하려면 Visual Studio 다운로드 페이지에서 "Build Tools for Visual Studio"를 받아 "C++를 사용한 데스크톱 개발"을 고른다.
- 개발자 명령 프롬프트에서 실행하면 `INCLUDE` 환경 변수를 그대로 쓴다.

## 더블클릭해도 CRuntime이 열리지 않는다

Windows가 해당 확장자의 기본 앱으로 다른 프로그램을 지정해 둔 경우다. 파일을 우클릭해 **"CRuntime으로 실행"**을 고른다. Windows 11에서는 "추가 옵션 표시"를 눌러야 보일 수 있다.
등록은 메뉴 **설정 → 탐색기 연결 등록**에서 한다. 해제는 **탐색기 연결 해제**다.

## 컴파일은 되는데 링크 오류가 난다

- `Symbols not found`가 나오면 해당 라이브러리를 `-l<이름>`이나 `-L<경로>`로 준다.
- 사용자 `.lib`가 정적 라이브러리면 JIT가 직접 연결하고, 임포트 라이브러리면 같은 이름의 `.dll`을 읽는다.

## 프로그램이 멈추거나 입력을 기다린다

표준 입력이 필요한 프로그램은 GUI 아래쪽 입력창에 한 줄을 쓰고 Enter를 누른다. 무한 루프는 종료 버튼으로 끝낸다. 작업 프로세스가 따로 있어서 GUI는 계속 응답한다.

## 내부 상태를 확인하고 싶다

- `-v`를 주면 컴파일 순서, 심볼 해석, 언와인드 테이블 등록 상황을 stderr에 출력한다.
- `--dump-ir <폴더>`는 소스별 LLVM IR을 `.ll` 파일로 기록한다. 이 옵션만 디스크에 쓴다.

## 종료 코드

| 코드 | 의미 |
|---|---|
| 2 | 컴파일 실패 |
| 3 | 입력 오류 |
| 4 | 툴체인(헤더) 없음 |
| 5 | JIT 초기화 또는 링크 실패 |
| 64 | 명령줄 인자 오류 |
| 그 외 | 실행한 프로그램의 종료 코드 |

## 알려진 문제

- 출력창에서 한 줄이 잘려 뒤로 밀려 나오는 현상이 한 번 보고되었다. 원인은 아직 확인하지 못했다.
